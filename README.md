# 🐺 Tomatobot

Discordで遊べる、シンプルな人狼ゲームBotです。

## 機能

- 人間プレイヤー1人から遊べるNPC対応
- 参加者は人間とNPCを合わせて最大15人
- 4〜15人からプレイ人数を選択
- 人狼・狂人・占い師・騎士・霊能者をロビーの増減ボタンで設定
- 基本6役: 村人・人狼・狂人・占い師・騎士・霊能者
- 昼の議論、投票、夜行動、勝敗判定
- 役職と夜行動はDMで通知
- ロビー・昼・投票・夜・結果を統一したパネルで表示
- パネル更新式の残り時間通知と匿名の投票進捗
- Discordの相対時刻による正確なフェーズ終了表示
- 投票集計・夜明け・結果表示の間を設けたフェーズ進行
- 同票時はNPCも性格と初回票を踏まえて再投票し、再同票なら処刑なし
- 投票後に得票数と「誰が誰へ投票したか」を公開
- DM送信失敗時の開始停止と役職を変えない再送
- 人数に応じた45〜90秒の議論時間
- 長い表示名でも崩れにくい参加者表示
- 前の試合結果を残したまま、同じメンバーで再戦
- NPCの会話・投票・占いと、CO情報を参考にした護衛・襲撃
- NPCごとの性格・疑い・投票記憶
- 占い発言と投票先の矛盾など、公開情報を使ったNPC推理
- プレイヤーが疑う相手と根拠を公開し、NPCを説得・誘導可能
- 公開情報に合う根拠は重く、事実に合わない断言は発言者への疑いとして反映
- 昼にNPCへ1人2回まで質問し、公開情報に基づく意見を全員で確認可能
- プレイヤーが占い師・霊能者の判定や騎士COを公開可能
- CO役職は試合中固定、潜伏中にたまった過去の判定もまとめて公開可能
- 人狼・狂人NPCは試合開始時に初日CO・2日目の潜伏解除・潜伏継続を決め、一度占い師COした後は毎日結果を公開
- 真占いは実際の未公開結果をワンクリックでCOでき、自由な結果選択も利用可能
- プレイヤーの占いCOをNPCの推理と投票に反映
- NPCとプレイヤーのCO表示を一行形式に統一
- 昼と投票中に、役職別のCO・判定一覧を確認可能
- 全員が早く行動しても、投票と夜に最低演出時間を確保
- 人間の占い師が夜に選ばない場合は、30秒後に未占いの相手を自動で占う
- 投票・疑い先は本人専用の選択欄を開き、自分自身を候補から除外
- 騎士は同じ相手を連続護衛でき、夜行動DM失敗時は自動選択した秘密結果を後から再送
- 4〜15人・通常/複数占い師/複数狂人を含む主要78配役の自動品質テストで、勝率・CO支持率・発言と投票の整合性を検証
- 人間プレイヤーの通算・連勝・役職別戦績をSupabaseへ保存
- `/stats` で自分の戦績を本人だけに表示
- ロビー開始・試合完走・中断・再戦・所要時間を進行データとして記録
- 試合終了後に「また遊びたい・ふつう・気になる点」をワンタップで送信

設定人数に足りない分は、ゲーム開始時にNPCが自動参加します。NPCがいないゲームでは、NPC発言やNPC用の疑い先メニューは出ません。NPCは外部AIを使わず、Bot内の軽量なルールで動きます。

1人プレイも4〜15人から人数を選べます。標準設定では7人・人狼1人です。人間とNPCを区別せず、現在の配役からランダムに役職を割り当てるため、人間が村人・人狼・狂人・占い師・騎士・霊能者になることもあります。配役に狂人を入れていない試合では狂人は選ばれません。NPC中心の試合では人数が増えても人狼は自動で増えないため、難しくしたい場合はロビーで人狼や狂人を追加できます。

## コマンド

| コマンド | 内容                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| `/jinro` | 募集を開始します。実行者は自動参加し、設定人数に足りない分は開始時にNPCが補充されます。 |
| `/reset` | 進行中のゲームを終了します。メッセージ管理権限が必要です。                              |
| `/stats` | 自分の通算・連勝・役職別戦績を本人だけに表示します。                                    |

## 役職編成

ロビーの「配役を変更」から各役職の人数を設定できます。残り枠は村人として自動計算されます。標準編成は次のとおりです。

狂人は人狼陣営ですが人狼が誰かは分からず、夜行動もありません。占い・霊能では「人間」と判定され、人狼が勝つと狂人も勝利します。勝利判定では狂人も「人間」の人数に含まれます。通常は占い師と狂人を各1人、騎士を2人、霊能者を1人まで設定できます。`BETA_TESTER_IDS` に登録したβテスターがホストの場合のみ、占い師は最大3人、狂人は最大2人まで設定できます。複数の真占いがいる構成では、設定人数までの占い師COを正常な枠として扱い、判定の一致・食い違いもNPCの推理へ反映します。βテスター専用の複数占い師・複数狂人構成は戦績へ記録しません。人狼陣営が村人陣営以上になる極端な初期構成は選択できません。

- 4人: 人狼1、占い師1、村人2
- 5人: 上記に騎士を追加
- 6人: 上記に霊能者を追加
- NPC中心の初期設定: 人狼1、占い師1、騎士1、5人以上では霊能者1、残りは村人
- 友達同士の目安: 7〜10人なら人狼2、11〜15人なら人狼3も設定可能

## セットアップ

Node.js 22以上が必要です。

```bash
npm install
```

`.env` を作成し、Discord Botトークンを設定します。

```env
DISCORD_TOKEN=your_discord_bot_token
PORT=10000
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SECRET_KEY=your_supabase_secret_key
```

```bash
npm run dev
```

## 確認

```bash
npm run ci
npm run playtest
npm run build
```

## デプロイ

`Dockerfile` と `render.yaml` を使用できます。Render側で `DISCORD_TOKEN`、`SUPABASE_URL`、`SUPABASE_SECRET_KEY`、`TOMATOBOT_ANALYTICS_HMAC_SECRET` を設定してください。秘密値はGitHubやDiscordへ貼らず、Renderの環境変数だけに保存してください。

戦績を有効にするには、SupabaseのSQL Editorで `supabase/migrations/202608110001_create_tomatobot_stats.sql` を一度実行します。プレイ状況と試合後の感想を記録するには、続けて `supabase/migrations/202608130001_create_tomatobot_play_analytics.sql` と `supabase/migrations/202608200001_enhance_play_analytics.sql` を順番に実行します。既存の旧版テーブルとは名前を分けているため、同じSupabaseプロジェクトでも共存できます。Supabaseが未設定または一時停止中でも、人狼ゲーム本体は通常どおり進行します。

プレイ記録には人数、配役構成、勝敗、日数、所要時間、中断地点、再戦のつながり、Botの版を保存します。人間プレイヤーはHMACで仮名化した識別子だけを保存し、新規・再訪や連戦数の集計に使います。参加者のDiscordユーザーID、表示名、会話内容、投票先、DMで送った個人の役職は保存しません。「その他」のコメントだけ、プレイヤーが任意で入力した場合に保存します。仮名IDを継続して比較できるよう、`TOMATOBOT_ANALYTICS_HMAC_SECRET` は長くランダムな専用値を設定し、運用中は変更しないでください。未設定でもゲーム本体と仮名参加者以外の試合記録は動作します。

JST基準の日次指標は、SupabaseのSQL Editorで `select * from tomatobot_play_daily_summary_v2 order by day_jst desc;` を実行すると確認できます。固有プレイヤー、新規・再訪、一人用・複数人、初戦から2戦目への継続率、中断地点、理由付き感想をまとめて表示します。D1・D7再訪は `select * from tomatobot_player_retention_cohorts order by cohort_day_jst desc;` で確認できます。
